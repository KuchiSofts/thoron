# Upstream #1313 on Thoron 158: processes that climb in CPU (2026-11-17)

ROADMAP **P5.3**. The report: Thorium 156.0.8078.28 (AVX2) on a laptop with a 10th-generation Intel Core processor
(Ice Lake) and Intel Iris Plus graphics (driver 31.0.101.2125), Windows 11 Enterprise Insider build 26300, hardware
acceleration switched off, five extensions (uBlock Origin, Dark Reader, OneTab, Tab Autopilot,
Tampermonkey). During normal browsing several background `thorium.exe` processes rose to about 12 % of
the processor each and the whole system to 88 %; then Windows showed "Unknown Hard Error" for
`thorium.exe` and the external monitor went dark. Its `chrome://gpu` showed
`eglCreateContext: Requested version is not supported` and a failed `GetGpuDriverOverlayInfo`. Chrome
156 and Brave 155 ran normally on the same PC, Thorium's version before 156 as well. It is very likely the
same reporter's laptop as #1230 (the same processor and Insider builds).

## What it points at

- "Unknown Hard Error" is a message box of Windows itself, shown when a process hits a system-level
  error it cannot name; with the external display failing at the same moment, the graphics driver is
  the first suspect, not the browser's own code.
- The two `chrome://gpu` errors are the graphics layer failing to get what it asks of that driver. With
  hardware acceleration off every page is drawn by the processor, so a heavy page (Dark Reader restyles
  every page) costs processor time in the GPU and renderer processes anyway.
- Neither the processor nor the driver nor the Insider build is on hand here, so the report itself
  cannot be reproduced on this PC.

## What was measured on Thoron

`tools/qa/cpu_trace.py`, for 60.0 minutes, on the Thoron 158 release build (158.0.8127.3010,
AVX2) while the 48-hour soak (`tools/qa/soak.py`, ROADMAP P5.4, Q.4) worked it: headless, so every page is
drawn by the processor as with hardware acceleration off, and every few seconds six heavy local pages
(DOM, images, script) opened and closed again. The trace read the processor time of every process of the
build's folder every 5 seconds (662 samples) and looked for any process above half a core
for more than two minutes. Windows 11 x64, AVX-512 processor, other programs running beside it.

| Process | Median, % of one core | 95th percentile | Most |
|---|---|---|---|
| Browser | 8.2 | 11.3 | 17.9 |
| GPU (drawing in software) | 4.1 | 6.4 | 17.9 |
| Renderers, together | 2.4 | 10.6 | 55.5 |
| Utility processes, together | 0.9 | 1.7 | 3.2 |

- **No runaway:** no process stayed above half a core for two minutes (0 found).
- **No climb:** the long-lived processes used, on average, in each quarter of the hour: the browser
  7.7, 7.5, 7.9 and 8.3 % of one core, the GPU process 4.0, 4.1, 4.0 and 4.4 %.
- **No pile-up of processes:** 9 to 19 processes, tabs opening and closing included.
- **Memory**, from the soak's own samples with every test tab closed: 298 MB at the start, 342 MB
  after 1.5 hours, while caches fill; the soak judges the trend only over its second half. The 8-hour
  soak of the same build passed with 2.1 MB per hour (`docs/perf/2026-11-16-soak-8h.md`).

## Conclusion

Not reproduced on Thoron 158 on this PC: under a constant load drawn in software, no process climbs or
stays busy, and the processes do not pile up. Memory over a long run is the soak's to judge (P5.4, Q.4). The report's own conditions are a particular laptop, driver and
Insider build with five extensions; to show it on Thoron or rule it out there, the same check needs a
PC like that (Intel Iris Plus, Windows Insider), with those extensions. The tool is ready for it:
`py -3 -I tools/qa/cpu_trace.py --browser-dir <folder of thoron.exe> --minutes 60` beside normal browsing.
